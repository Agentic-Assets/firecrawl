# CRE Collector Lessons 2026-06-11

## Operational Lessons

- The production path is `cre_collector`, not `cre_scrapers`. Future agents should start with `collect.ts`, `cre_ingest.py`, `cre_daily_update.sh`, and this directory's docs.
- Full collection is fast enough for a daily local run. Latest measured full run took `27:01.56` at `--page-cap=400 --concurrency=3`.
- Live ingest should be additive unless every source is clean. Lee failed in the latest run, so `--mark-missing` was intentionally skipped.
- Buildout feeds can return HTML interstitials after many pages. Retrying individual pages is useful, but a source-level abort threshold is necessary to prevent gappy artifacts from causing bad reconciliation.
- Cache Buildout failures across sale and lease passes. Without this, Lee can spend time failing twice against the same full inventory feed.
- SVN and Lee use the same Buildout-style inventory semantics, but fresh 2026-06-12 probes showed both can enter a temporary 403 state after sustained paging. Treat Buildout as rate-limit sensitive, require complete page coverage for reconciliation, and do not use `--mark-missing` after Buildout page failures.
- Savills can render US sale rows with city/state/ZIP in inconsistent forms. The parser needs state names, state abbreviations, ZIP-only rows, and foreign fallback filtering.
- Newmark's Algolia API is the best current path. State facets alone are not enough when a state crosses the 1,000-hit cap, so property-type sub-splitting matters.
- NAI Global's best path is the public Infabode GraphQL feed plus
  `publicPost(id)` detail enrichment, not rendered widget cards. The feed pages
  back to 2021 and includes historical or ambiguous statuses, so active EQUIRE
  ingestion must keep only `listingStatus` values containing
  `FOR_SALE_ON_MARKET`. Do not ingest `UNKNOWN`, `SOLD`, `UNDER_OFFER`, null, or
  detail-failure rows into the active listing table.
- Cushman's rendered Coveo page was the wrong bulk path. The working path is `/api/properties/search` with `rfkId=property_search`, `view=pins`, `site_country=US`, `listing_type=Buy|Lease`, `limit=100`, and `offset=N`, fetched through local Firecrawl. Detail enrichment must scan raw HTML for `assets.cushmanwakefield.com/-/pmedia/...` because PDF links can be absent from Firecrawl's extracted links.
- For documents and images, collect URLs and metadata only. Bulk downloading PDFs/images would create avoidable storage cost and is not needed for EQUIRE listing discovery.
- Avison Young, Marcus & Millichap, NAI Global, and JLL Investor remain useful but limited sources. Document their limits instead of inflating coverage.
- CBRE Deal Flow's best path is the public RCM ListingEngine endpoint, not the rendered homepage. The public filter can report a larger total than the cards exposed by paginated HTML. Store the observed public-card count and the reported total separately.
- Transwestern has a public GET feed at `transwestern.com/properties?call=ajax...`; it is no longer a POST-only blocked source in code, but still needs full-run and live-ingest proof.
- Transwestern full ingest on 2026-06-12 staged 2,021 unique rows after
  `Sale or Lease` duplicates merged. The public feed/detail path is complete,
  but the first full artifact's description fallback was footer/TREC boilerplate
  on every row. Keep the Transwestern description guard and prefer null
  descriptions over loading site footer text.
- Colliers main `www.colliers.com/en/properties` should stay blocked until a
  practical public GET path, Firecrawl action path, or authorized integration
  exists. Colliers SalesTracker is a separate partial investment-sale path
  through public RCM GET endpoints and should not be described as complete
  Colliers sale plus lease coverage.
- Colliers SalesTracker public totals need separate labels. RCM reported
  `total=1653` and `totalAvail=2094`, but public card pagination exposed 1,300
  unique cards and 1,172 unique upsert rows after repeated ProjectIds.

## Supabase Lessons

- `cre_ingest.py` should continue using `psql` plus `POSTGRES_URL_NON_POOLING` or `POSTGRES_URL`. This avoids committing or printing service-role keys.
- The collector-owned `cre_*` tables and `v_cre_*` views are private to service-role reads. RLS with no public row policies is intentional for this listing surface.
- Supabase advisors are noisy across the broader EQUIRE project. For this collector, verify the collector-owned `cre_*` tables, functions, views, and indexes directly.
- `search_cre_listings` and `update_cre_listing_timestamp` must keep `SET search_path = ''`.
- All collector-owned foreign keys had covering indexes during the 2026-06-11 verification pass.
- psql reported a project-level collation version warning. That is outside the collector, but future database maintenance should track it.
- Source-specific additive ingests can be valid without `--mark-missing`. CBRE Deal Flow live ingest on 2026-06-12 staged 1,836 rows and left earlier additive probe rows active by design.
- Colliers SalesTracker live ingest on 2026-06-12 staged 1,172 unique sale rows
  with 0 missing URLs, titles, raw data, bad states, impossible coordinates,
  duplicate external IDs, or child orphans. It should remain additive until
  main Colliers Coveo coverage is solved.
- NAI Global active-status-filtered ingest on 2026-06-12 staged 241 active
  Infabode rows and safely used source-scoped `--mark-missing` to soft-delete 19
  older rendered-card probe rows. This is the right pattern only after a clean
  full enriched feed plus explicit source-status policy.
- Cushman & Wakefield full API ingest on 2026-06-12 staged 11,318 rows and
  safely used source-scoped `--mark-missing` after a clean full run with matched
  source totals and 0 detail errors. This replaced the old shallow 24-row probe
  state with a complete public API feed and rich URL-only details.
- Transwestern live ingest on 2026-06-12 required seeding the `transwestern`
  brokerage slug in the live database first, then staged 2,021 active rows with
  source-scoped `--mark-missing`. Validation found 0 bad descriptions, bad asset
  URLs, missing URLs/titles/raw data, duplicate external IDs, bad states,
  impossible coordinates, malformed guarded prices/cap rates, or child orphans.
- Lee's Buildout issue was sustained-run throttling/non-JSON behavior, not
  permanently bad pages. The durable page-window cache solved the production
  path: fill small windows with `BUILDOUT_CACHE_ONLY=1`, then assemble only
  with `BUILDOUT_ASSEMBLE_FROM_CACHE=1` after every expected page is present.
  Cache-only windows intentionally return nonzero and write no listing artifact.
  Treat `0 selected page(s) missing` as the cache-fill success signal.
- Buildout assemble-from-cache mode must not use recovery or network fallback.
  A failed assemble should identify missing pages and stop; otherwise it can
  accidentally fill cache outside the intended pacing window.
- For Buildout source counts, raw rows can exceed staged rows by design. The
  ingestor strips `-sale` and `-lease` from URL `propertyId` values for SVN and
  Lee, merging dual-mode properties into `sale_or_lease`.
- JLL detail enrichment should target detail-page `__NEXT_DATA__`; Newmark
  detail enrichment should target cached Algolia People lookup by exact
  `broker_name`, not noisy site shells.
- Marcus & Millichap full public sale collection is direct-public-HTTP, not
  Firecrawl-dependent. Use public `mapproperties` ActivityIds, public
  `mappropertydetail` tiles, and direct detail HTML. Keep deal-room URLs in raw
  metadata only because anonymous access redirects to MyMMI sign-in.
- Long detail-enrichment sources need per-row checkpoints. The Marcus full run
  was interrupted after 1,320 of 3,126 details before any final JSON was written;
  a JSONL detail cache beside the output artifact made the subsequent full run
  resumable and enabled a fast retry of five transient `fetch failed` rows.
- Do not cache failed detail rows as good results. Cache reads should skip
  `detailError` rows and cache writes should avoid appending them, so transient
  failures can be retried without throwing away a full run.
- The live `credeals.search_cre_listings` function now has the five-argument
  signature `query, p_city, p_state, p_type, p_transaction` and returns
  `brokerage_name`, not `brokerage_slug`. Validation snippets should use the
  current signature.
- Local Firecrawl healthcheck can fail at the Docker/OrbStack layer while
  direct-public-API collectors still work. Record that distinction instead of
  treating every collector as blocked by `localhost:3002` being down.

## Documentation Lessons

- Keep `START_HERE.md` as the high-signal session entrypoint.
- Keep `HANDOFF_LOG_2026-06-11.md` as the detailed chronological evidence log.
- Keep `CLAUDE.md` files short enough to orient agents, and push run evidence into handoff/status files.
- When source counts change, update both `cre_collector/CLAUDE.md` and the system design doc.
- Do not let old Python-package docs imply the legacy scraper package is the daily production path.

## Verification Pattern

Use this order for future changes:

```bash
bash scripts/firecrawl-ops/firecrawl_healthcheck.sh
cd scripts/firecrawl-ops/cre_collector
npm run typecheck
python3 -m py_compile cre_ingest.py
npx tsx collect.ts --source=savills,nai-global,newmark --transaction=both --max-items=3 --page-cap=5 --concurrency=2 --out=/tmp/cre_probe.json
python3 cre_ingest.py --in /tmp/cre_probe.json --dry-run --keep-artifacts /tmp/cre_probe_ingest
```

Run a full collection only after this probe path is clean. Ingest full artifacts additively unless all source errors are understood and acceptable for reconciliation.
