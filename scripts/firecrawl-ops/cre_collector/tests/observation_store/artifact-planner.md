# Synthetic Buildout fixture planner

Part of [AGENTIC-2902](https://linear.app/agenticassets/issue/AGENTIC-2902). This is an offline fixture experiment, not a production writer or collector integration. It has no database client, network access, scheduling or lifecycle authority. The separate test runner creates only a disposable synthetic PostgreSQL cluster with a random fixture database name and no TCP listener.

The planner verifies an original, a Buildout artifact and a matching manifest in memory, then returns fixture-function arguments. It retains the complete already-quarantined artifact and its records, including unknown nested facts and duplicate/conflicting ordered attributes. It submits only the original hash and byte length, never the original bytes. Claimed source, generation, page and transaction remain operator assertions; missing identity, generation, page and address do not establish completeness or authorize promotion. The receipt page is an internal slot, not a publisher-page claim.

Only a synthetic fixture with the selected Buildout source label is accepted. Both labels are caller-controlled tripwires, not authentication or proof of rights. JLL and unknown sources are excluded. The builder's heuristic quarantine does not guarantee confidentiality, source visibility, or safe disclosure. The original must remain private and unchanged to recover omitted evidence and original numeric spelling. Production use requires source-specific disclosure controls, independently reviewed privacy and retention, rights, restricted access, ownership and production DDL/write approval. JSONB does not preserve every original numeric lexical spelling.

Run from a standalone no-hardlinks clone: `python3 -m pytest tests/observation_store/test_buildout_observation_fixture_planner.py -q`; then `python3 tests/observation_store/run_buildout_observation_fixture_planner_postgres.py --execute-disposable-fixture`. The latter takes no database URL and refuses to run without its fixture flag.
