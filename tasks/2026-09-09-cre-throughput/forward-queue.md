# Candidate follow-ups after CRE throughput experiments, 2026-09-09

This is an evidence-linked menu, not a separate work ledger or committed roadmap. [AGENTIC-1229](https://linear.app/agenticassets/issue/AGENTIC-1229) owns the active refresh.

1. **Sustained live detail recovery** (P1, evaluation, verified remaining gate): observe the resumed patched-browser generation for new detail successes and failures, then verify each source's complete certificate and database readback. Do not use cache replay speed as new-fetch throughput.
2. **Default-off direct transport admission** (P1, hardening, verified boundary): run a new immutable JLL generation with the pinned helper only after full source coverage and fallback/ingest review. Compare source assets and canonical identity; do not switch a partially completed generation's collector SHA.
3. **Resolver failure diagnosis** (P2, robustness, hypothesis): retain explicit DNS-unavailability metrics and timeout context so a new cascade can be distinguished from source denials. The original initiating failure is not proven.
4. **Repeatable benchmark harness** (P2, process, verified opportunity): promote the ignored experiment into a fixture-driven tool with exact requested/observed sample counts, valid-content throughput, start-gap checks, and no database credentials or stored source bodies.
5. **Upstream integration** (P2, compatibility, verified scope): handle the 23-conflict merge in a separate reviewed branch. Evaluate asynchronous PDF extraction/semaphore, fetch cookie isolation, and Redis completion recovery with their own regression tests. They are not established fixes for this JLL incident.
6. **Eight-worker evaluation** (P3, performance, short-sample evidence only): reconsider only with sustained provider-safe pacing, asset fidelity, backpressure and CPU measurements. The eight-worker diagnostic does not justify a general production setting.
