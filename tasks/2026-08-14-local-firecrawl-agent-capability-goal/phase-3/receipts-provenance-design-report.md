# AGENTIC-2281 receipt and provenance design

Date: 2026-08-14
Scope: read-only design review of the consolidated local-agent worktree. This
report does not authorize runtime, model, Docker, CRE, Linear, or upstream API
changes.

## Decision

Ship a small **agent-safe receipt v1** as the terminal, body-free record for a
bounded helper operation. It must be an auditable statement about the local
tool invocation and its projected outcome, not a copy of the request, source,
API response, job handle, or structured result. Keep a metrics artifact and a
receipt manifest as a pair; the manifest is the terminal record and contains
only an opaque reference to the adjacent metrics artifact.

This fits AGENTIC-2281 now. It does not depend on a model, does not change the
CRE collector boundary, and can reuse the in-progress `--agent-safe`
`firecrawl_request.py` path rather than introducing a second client or
telemetry service.

## Evidence reviewed

- `scripts/firecrawl-ops/firecrawl_request.py` already has a narrow
  `--agent-safe` mode, requires `--metrics-only` plus a task-local receipt
  directory, rejects profile/AI/raw-output options before dispatch, and emits
  `agent-safe-receipt-v1` plus projected metrics.
- `scripts/firecrawl-ops/tests/test_firecrawl_agent_safe.py` already proves
  source markdown and a URL are absent from a scrape/parse receipt pair, and
  covers the unknown-submit crawl terminal case.
- `scripts/firecrawl-ops/local_agent_preflight.py` produces a body-free,
  versioned document with a strict UTC `observed_at` and an
  `evidence_digest`. It intentionally leaves async work `degraded` until a
  trusted smoke-producer contract exists.
- `scripts/firecrawl-ops/firecrawl_compatibility_doctor.py` produces a
  body-free normal-pin/JSONL diagnostic and exposes the compatibility manifest
  SHA-256. Its opt-in `--run` is loopback-only.
- The phase-2 pilot design reserves `--receipt-dir` for a path-independent
  receipt and says AGENTIC-2281 is the place to generalize it. The current
  helper is therefore the correct single implementation seam.

## Required v1 contract

Use JSON schema draft 2020-12 (or the repository's existing light validator if
third-party JSON schema support is deliberately avoided) with
`additionalProperties: false` at every object. Use an integer
`schema_version: 1` and a stable `kind: "firecrawl.agent-safe-receipt"`; a
schema change is a new version, never an undocumented optional field.

```json
{
  "schema_version": 1,
  "kind": "firecrawl.agent-safe-receipt",
  "receipt_id": "3b6d...32-hex-lowercase...",
  "observed_at": "2026-08-14T15:04:05Z",
  "recipe": "scrape",
  "api_scope": "loopback-http-3002",
  "producer": {
    "interface": "firecrawl_request.py --agent-safe",
    "helper_sha256": "sha256:<64-lowercase-hex>",
    "tooling_manifest_sha256": "sha256:<64-lowercase-hex-or-null>"
  },
  "preflight": {
    "required": ["base_http"],
    "observed_at": "2026-08-14T15:04:03Z",
    "evidence_digest": "sha256:<64-lowercase-hex>",
    "status": "passed"
  },
  "input": {
    "kind": "public_https_url",
    "retained": false,
    "content_sha256": null
  },
  "bounds": {"request_timeout_seconds": 30.0},
  "outcome": {
    "terminal_disposition": "accept",
    "reason_code": "http_success",
    "body_retained_bytes": 0,
    "metrics_artifact": {
      "artifact_ref": "firecrawl-agent-safe://v1/<receipt_id>/metrics",
      "sha256": "sha256:<64-lowercase-hex>",
      "bytes": 94
    }
  },
  "redaction": {
    "source_body_retained": false,
    "request_value_retained": false,
    "absolute_path_retained": false,
    "secret_value_retained": false
  }
}
```

The receipt should use a strict RFC3339 UTC `Z` timestamp (seconds with an
optional fractional part), reject future values when validating externally,
and use `sha256:<hex>` everywhere rather than mixing prefixed and bare
digests. `elapsed_seconds` is useful only if finite, non-negative, and bounded
by the configured timeout plus a small documented serialization allowance.

`preflight` must be generated by the same invocation from the actual
`local_agent_preflight.py` document, never accepted as a caller-supplied
digest. For a POST pilot, require `base_http=ready`; for crawl also require a
successful queue/active-crawl observation and zero active crawls before
submission. Store only the preflight digest and timestamp, not its complete
observations. The compatibility manifest digest is provenance for the tool
contract, not proof that a package was installed or a doctor `--run` passed.

Input-policy or preflight rejection happens before the safe request and writes
no helper receipt: the preflight document is its own body-free evidence. Once
an allowed request begins, however, write exactly one terminal receipt for
every outcome, including HTTP failure, malformed response, crawl failure,
timeout, and transport failure. Map transport exceptions to a fixed
`transport_unreachable` reason code; never serialize exception text or a URL.

## Redaction rules and current gaps

The current draft is a strong start but needs these changes before calling it a
general AGENTIC-2281 receipt:

1. Do not retain `args.api_url` as `origin`; use the fixed
   `api_scope` label. It is currently benign after canonicalization, but it is
   unnecessary data and makes the contract broader than needed.
2. Do not put the task directory or generated filename in `artifact_ref`.
   Although relative, `tasks/<caller supplied>/...` is still a raw filesystem
   path and may contain a client or project name. Use the opaque logical URI
   above. The manifest's containing directory is the local resolver context.
3. Do not persist raw crawl/batch/extract IDs. `response_metrics()` currently
   admits an `id`/`jobId`; a local job ID can be a bearer-like handle to later
   output. Omit it in agent-safe metrics. A separate interactive (non-safe)
   caller can retain its ID outside this receipt path.
4. Do not retain a SHA-256 of an arbitrary URL with query material. The helper
   currently allows a query and computes `input_sha256`; this is a durable,
   dictionary-testable representation of signed URLs or tokens. For the safe
   public pilot either reject query/fragment URLs or omit target digests
   entirely. `repository_file` may retain its content SHA only for an approved
   public fixture; it must never retain the file path.
5. Project metrics through a per-recipe whitelist. Permit only booleans,
   non-negative bounded counts, known terminal status enums, bounded HTTP
   status, and a fixed reason-code enum. Never copy arbitrary `status`, `id`,
   `error`, `message`, metadata, header, or server values into metrics.
   Implement this as an agent-safe projector rather than narrowing the
   existing general `response_metrics()` function: ordinary operator workflows
   intentionally retain crawl IDs for follow-up polling, and their established
   tests must remain unchanged.
6. Add `observed_at`, a versioned `kind`, strict schema validation, and an
   explicit redaction declaration. `body_retained_bytes: 0` alone is not a
   proof that URLs, paths, job handles, or secrets were withheld.
7. Write the metrics file first and the manifest last. A complete manifest is
   the commit marker; an orphan metric after interruption is not a terminal
   receipt. Keep both file names opaque and UUID-derived, but do not serialize
   the filesystem names in the manifest. Write each to a same-directory
   temporary file and `os.replace` it so a torn manifest is never mistaken for
   a receipt.
8. Route all `--agent-safe` HTTP through a dedicated opener with
   `ProxyHandler({})` and a rejecting redirect handler. The current generic
   `open_request()` uses `urlopen`, which can honor ambient proxy variables and
   follow a redirect even though validation canonicalizes the initial API
   origin. This is an AGENTIC-2279 prerequisite: a receipt must not certify a
   request that escaped the local transport boundary.
9. Redact safe-mode terminal diagnostics too. `poll_crawl()` currently builds
   timeout/failure `SystemExit` messages containing the raw crawl ID. The
   projected receipt drops the `error` field, but the agent's stderr can still
   retain the handle. Use fixed reason codes such as `crawl_timeout` and
   `crawl_failed`; preserve the raw ID only in process memory needed for the
   bounded poll.
10. Restrict the first safe parse release to the approved tracked public PDF
    fixture and its expected SHA-256. The present "relative path within the
    repository" check would permit `parse .env` and upload configuration
    secrets to the local API. A later founder-approved general local-file mode
    can define a separate authorization and retention contract; it is not part
    of the AGENTIC-2279 pilot or AGENTIC-2281 receipt v1.
11. Restrict the initial safe scrape/map/crawl target to the exact public
    `https://example.com/` pilot fixture. The current HTTPS-only check still
    admits loopback, private-network, and DNS-rebinding candidates that the
    Firecrawl container could fetch. General host authorization needs the
    sandbox/ingress decision work in AGENTIC-2283/2284, not an ad-hoc resolver
    in this helper.
12. Exclude standalone `crawl-status` from the first safe interface. It lets a
    caller supply an existing local job handle, which can cross into another
    workload even when receipt projection is redacted. Safe polling should use
    only the ID returned in memory by the immediately preceding one-page safe
    crawl; it is never printed or persisted. Keep normal `crawl-status` for
    operator workflows.

## Exact test matrix

Add focused tests beside `test_firecrawl_agent_safe.py`; no API snip is needed
for this pure projection/receipt contract.

| Test | Expected assertion |
|---|---|
| Valid v1 scrape, map, crawl terminal, crawl unknown-submit, and fast PDF parse fixtures | Each manifest and metrics artifact validates; terminal disposition is one of `accept`, `manual_review`, `reject`, `unknown`; artifact digest matches exact bytes. |
| Receipt schema negative table | Reject extra properties, non-UTC/invalid/future timestamps, bare or malformed SHA-256, non-finite elapsed time, unknown recipe/status/reason code, and mismatched artifact digest. |
| Secret injection | Put unique sentinel strings in source markdown/HTML, response error/message, URL query/fragment, auth/header values, directory input, uploaded file name/path, and job ID. Assert each sentinel is absent from stdout, stderr, metrics, manifest, and any printed artifact reference. |
| Job-handle boundary | A successful crawl response with `id`/`jobId` emits no raw ID and does not expose a hash that enables polling. The only retained handle is the opaque receipt ID. |
| Safe terminal diagnostics | Crawl timeout, failed/cancelled status, malformed response, and transport failure emit a fixed reason code and retain no raw crawl ID, request value, or local file path on stdout/stderr. Every failure after an allowed request begins writes exactly one terminal receipt; input/preflight rejection writes none. |
| Path portability | A receipt directory containing a distinctive caller/path string produces no absolute or relative path in either artifact; `artifact_ref` is the stable logical URI. Reject absolute, `..`, and symlink-escape directories before an HTTP request. |
| Input provenance | Safe URLs with query/fragment are rejected before HTTP, or, if later explicitly supported, prove no target value/digest enters either artifact. Public fixture parse retains only its content SHA and `input.kind`, never its path. |
| Fixture boundary | `--agent-safe parse` rejects `.env`, arbitrary repository files, symlinks, non-PDF paths, and a known fixture with the wrong SHA before multipart construction or HTTP. The approved test PDF alone takes the fast, one-page path. |
| Target boundary | Safe scrape/map/crawl accepts only the canonical `https://example.com/` fixture in this release and rejects loopback, RFC1918/literal-IP, non-default-port, query/fragment, and other hosts before HTTP. |
| Job ownership | Standalone `crawl-status --agent-safe` is rejected before HTTP; an approved `crawl --wait` may poll only the submit ID held in that process. Normal operator `crawl-status` behavior remains available outside safe mode. |
| Preflight linkage | Mock a real-shaped fresh preflight document and prove its computed digest/timestamp are recorded only after `base_http` is ready. Unavailable/stale/malformed/active-crawl preflight prevents POST and writes no receipt. A caller-provided fake digest cannot alter the receipt. |
| Transport boundary | With proxy environment variables set and a redirecting loopback test server, safe mode rejects before a redirected request can be made; the generic non-safe helper behavior remains unchanged. |
| Metric allowlist | Inject arbitrary strings in every API response field; only documented numeric/boolean/enum metrics survive. Validate failures and upstream raw errors still produce a redacted terminal receipt when a request was made. |
| Write order | Simulate a metrics write failure and a manifest write failure. No manifest appears until metrics are complete; a partial/orphan artifact is not reported as a receipt; temporary files are atomically replaced and cleaned. |

Use `pytest` for the module suite, `ruff check`, `ruff format --check`, and
`py_compile` after implementation. Run one bounded non-AI public or synthetic
pilot only after the same-run preflight and compatibility gates are positive;
its checked-in report must include only the receipt pair, never a raw helper
response.

## AGENTIC-2282 separation

AGENTIC-2282 remains blocked: the upstream structured-output fallback PR has
not merged and there is no named in-repo consumer. Do not add model, prompt,
schema, response, fallback, or `structured_output` fields to receipt v1. A
receipt cannot prove AI output quality, and storing model output or a request
schema would violate the body-free contract.

After its stated gate is met, AGENTIC-2282 should define a separate
`structured-output-provenance-v1` artifact with only: a named consumer ID,
upstream merge SHA, schema digest, producer/fallback implementation digest,
bounded attempt count, fallback-used boolean, result validation boolean, and
an opaque output artifact reference. It must exclude prompt, URL, model
response, extracted values, headers, provider key, and raw model/provider
error. Connect a future general receipt by referencing that separate artifact's
digest, not by widening receipt v1. Require a dedicated named-consumer snip
and invalid-JSON/schema-mismatch fallback tests before any runtime claim.
